# 帽书写作规范(hatbook-writer)

本 skill 是《一顶帽子的全球旅行》正文写作的唯一标准。它由作者(用户)与 Claude 在 2026-07 共同推导并确认,替代此前"词典条目式"的旧写法。

## 一、这本书是什么

- **读者画像**:准备入行做帽子生产/外贸生意的零基础成年人。不是学生,不是猎奇者——他读完是要拿去用的、要拿真金白银下单的。
- **深度定级:从业者级。** 每个知识点写到"读者可以拿着它与工厂/货代/客户平等对话且不露怯"的深度,而不是"知道有这回事"。工厂内部管理细节写到能对话的程度;**与读者的钱直接相关的章节(报价、打样、验货、物流、海关退税、算账、获客)写得比其他章更厚。**
- **声音**:一位带徒弟的老师傅。直接、具体、不端着;敢说行业潜规则,但每个判断给出机制层面的解释,不装神秘。
- **主线**:一个虚构的加拿大精酿啤酒厂客户订500顶logo绣花帽,贯穿全书。每章开头用主线订单推进到本章环节的一幕开场。
- **虚构声明**:书中案例与对话为教学虚构(基于行业常见情形构造),第0章统一声明一次。写作时案例要有"真实质感":具体的数字、具体的对话、具体的时间线,禁止"某客户曾经……"式的模糊案例。

## 二、三级小节写作模板(核心)

正文以三级小节(如 4.2.1)为最小写作单元。**每个三级小节 ≥1000 字**(中文字符计,不含标题),按以下五件套组织,每小节至少覆盖其中四件,顺序可调但"场景开头、动作收尾"不变:

1. **场景/画面**:把读者带到现场。写到读者闭眼能看见的程度——空间多大、谁在做什么动作、东西长什么样、声音气味。没有画面的知识记不住。
2. **机制**:原理讲透。不只说"是什么",要说"为什么是这样"、"不这样会怎样"。允许适度展开上下游因果链。
3. **数字锚点**:不只给区间,要**带着读者算一遍**——用主线订单(500顶)或一个具体量级代入计算,或给出可用的判断阈值("超过X就有问题")。数字要长在故事上。
4. **事故/对话**:一个本知识点对应的翻车小案例,或一段真实质感的对话(读者问、跟单员/老板/货代答,标出哪句是真话哪句是托辞)。读者靠"原来会这样出事"记住知识。
5. **动作**:落到可执行——一句可直接抄去问工厂的话、一个写进PI/规格书的条款、一个验货时的检查动作、一个决策规则。

**反面清单(出现即不合格)**:
- 只有定义+一句提醒的"词典条目"
- 用"要注意""建议做好"这类没有具体动作的空话收尾
- 罗列式 bullet(三个词一行)充当正文——bullet 只用于真正的并列枚举,且每条要展开成完整句群
- 未在第一部定义过的术语裸奔出场(新术语必须现场定义,或标注"见X.X.X")

## 三、章级固定件

每章除小节正文外,固定包含:

- **章首"主线推进"**(200-400字):啤酒厂500顶订单走到本章对应环节的一幕,以读者视角开场,自然引出本章要解决的问题。
- **章末"本章工具"**:把散在正文里的"动作"汇总成可直接使用的清单/话术卡/检查表(如:催单五问、验布三看、交期起算条款模板)。
- **章末"本章作业"**:一个低成本可执行的动手任务(blockquote 格式,以"**本章作业**:"开头)。
- 章末以斜体给出下一章指引。

## 四、全书一致性规则

- **术语纪律**:术语只在首次出现处定义(第一部第1-4章是术语宪法);之后引用写"(见X.X.X)"。重写时若发现术语首次出现位置变化,同步更新交叉引用。
- **交叉引用格式**:统一"(见X.X.X)"或"(第X章会展开)",不用页码。
- **数字口径**:同一数字全书一致(如帽子出口退税约13%、单顶用布0.15-0.18㎡、绣花¥0.35-0.55/千针)。新增关键数字时检查是否与已写章节冲突。
- **排版**(适配网页阅读器,markdown 渲染):表格用于对照类信息;流程用代码块画箭头链;重点用**加粗**;吊牌作业用 blockquote;不用一级标题以外的编号体系。
- **主线时间线**:主线订单的进度在各章之间必须连续,不可倒流或跳跃(第4章布已上裁床,第9章回忆报价时用过去时)。

## 五、写作与审查流程(主agent-辅助agent流水线,必须遵守)

写作以"**辅助agent执笔、主agent审查**"的方式连续推进,**无人工审查环节**,整书按目录顺序尽速完成。

1. **执笔(辅助agent)**:每章由一个辅助agent一次写完——章首"主线推进"+目录全部最深层小节+章末"本章工具"与"本章作业"。开工前必读:本 SKILL.md 全文、OUTLINE.md 本章目录、CANON.md(主线时间线/人物/数字口径/术语索引)、chapters/ch01.md(深度与口吻校准样板)、本章旧版底稿(若有,只参考知识点覆盖面,文字全部重起)。写作以目录最深层小节为单元,逐节对照下方检查表自审,不合格当场重写。
2. **审查(主agent)**:收稿后按四项审查,不合格退回重写或直接修订:
   - ① **内容质量**:对照检查表与反面清单抽查深读,从业者级深度不打折;
   - ② **标题符合度**:每个小节写的必须就是标题说的事,跑题即退回;
   - ③ **内容完整度**:目录单元一个不缺、每单元≥1000字(脚本核验)、章级固定件齐全;
   - ④ **前后连贯性**:主线时间线与 CANON.md 一致且不倒流、术语只在首次出现处定义、交叉引用编号正确、数字口径与已写章节无冲突。
3. **入库(主agent)**:审查通过后更新 CANON.md(登记本章新增术语/关键数字/主线进度)→ 同步 OUTLINE.md 状态、toc.md、build.py 的 FILES、模板 CHAPTERS 的 done 标记 → `python3 build.py` 构建校验 → git 提交推送。

**逐小节自审检查表**:
- [ ] ≥1000字(不含标题)?
- [ ] 五件套至少占四件?场景开头、动作收尾?
- [ ] 有至少一处"带着读者算"或明确阈值?
- [ ] 事故/对话有具体数字、具体台词,不是模糊案例?
- [ ] 所有术语要么此处首次定义、要么带(见X.X.X)?
- [ ] 通读一遍:有没有任何一句是"删掉也不损失信息"的填充句?有则删,删后不足1000字则说明深度没挖够,继续挖而不是注水。
- [ ] 从业者读到会不会觉得外行?(自问:一个做了十年帽子的跟单员看到这段,会点头还是摇头?)

**字数与深度的关系**:1000字是下限不是目标。字数不足的正确解法永远是往深挖(多一层机制、多一个算例、多一段对话),绝不是形容词注水。若某小节题目实在撑不起1000字,说明目录颗粒度有问题——提出与相邻小节合并,而不是硬凑。

## 六、目录基准

全书结构以对话中确认的三级目录为准(6部28章+尾声+附录,详细到 X.X.X)。重写过程中如需调整小节划分(合并/拆分),先向用户说明理由并获确认,再动目录。
